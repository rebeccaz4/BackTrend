# BackTrend

**BackTrend** is a benchmark for *weak-signal prediction* in scientific and technological research: given a target topic and an early time window, can a system surface the sub-directions ("weak signals") that were rare early on but grew into meaningful research activity later?

This repository ships the **code, documentation, configuration, and the human-validated ground-truth signals** (`construction/weak_signal.json`) needed to reproduce the benchmark end to end. Generated corpora, model outputs, and scored results are **not** included — they are produced by running the pipeline (see [Reproducing the benchmark](#reproducing-the-benchmark)).

The dataset of verified weak signals is mirrored on Hugging Face: [`rebeccazzzz/BackTrend`](https://huggingface.co/datasets/rebeccazzzz/BackTrend).

## Repository layout

```
BackTrend/
├── construction/          # Build ground-truth weak signals from bibliographic corpora
│   ├── scripts/           #   fetch → extract → dedupe → match → compute
│   ├── topics.json        #   target topics (25) + paraphrases  [input config]
│   ├── weak_signal.json   #   human-validated ground truth (66 signals, 18 topics)
│   └── README.md          #   construction pipeline guide
├── prediction/            # LLM / agentic weak-signal predictions
│   ├── *.py               #   one script per model/method
│   └── prediction_guide.md
├── evaluation/            # Five-way evaluation of predictions vs ground truth
│   ├── run_all.py         #   main runner
│   └── evaluation_guide.md
├── requirements.txt       # Python dependencies
└── LICENSE
```

## Installation

From the repository root:

```bash
pip install -r requirements.txt
```

This covers construction, the API-based prediction scripts, and evaluation. The local-inference systems need extra packages that are **not** installed by the command above — see the commented block at the bottom of `requirements.txt`:

| To run | Also install |
| --- | --- |
| `qwen3_8B_rag.py`, `qwen3_30B_rag.py` | `vllm`, `llama-index`, `llama-index-embeddings-huggingface` |
| `DR_Tulu_eval.py`, `Tongyi_eval.py` | `vllm` (+ `qwen-agent` for Tongyi), plus the upstream repos below |
| `dedupe_candidates.py --cluster-provider local` | `sentence-transformers` |

Some scripts read credentials from environment variables or a local `.env`: `SEMANTIC_SCHOLAR_API_KEY` for paper retrieval, `OPENAI_API_KEY` + `OPENROUTER_API_KEY` for construction, `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` for prediction, and `OPENROUTER_API_KEY` for the LLM judge. Each stage's guide lists exactly which keys it needs. `.env` is git-ignored; never commit keys.

### Upstream agent repositories

The two DeepResearch systems are **not** vendored here. Clone them yourself and point the eval scripts at the clones with `--dr-tulu-dir` / `--tongyi-dir`:

```bash
git clone https://github.com/rlresearch/dr-tulu.git dr-tulu-main
git clone https://github.com/Alibaba-NLP/DeepResearch.git Tongyi-DeepResearch-main
```

`DR_Tulu_eval.py` needs the clone's `agent/` directory and defaults to `./dr-tulu-main`; `Tongyi_eval.py` needs the clone's `inference/` directory and takes `--tongyi-dir` as a required argument. Both scripts patch a few files inside your clone at run time (temporal cutoff enforcement), so use a dedicated checkout rather than one you rely on elsewhere. See [`prediction/prediction_guide.md`](prediction/prediction_guide.md) for details.

## Reproducing the benchmark

The three stages run in order — each consumes the previous stage's output.

### 1. Construction — build the ground-truth weak signals

For a target topic, fetch its 2019–2024 paper pool, extract and cluster candidate sub-topics, match later adoption through references, and score each candidate to obtain the final weak signals. See [`construction/README.md`](construction/README.md).

```bash
bash construction/scripts/run_final_pipeline.sh --topic "large language models"
```

This produces the per-topic weak-signal **candidates** under `construction/final_results/`. The final, human-validated ground truth consumed by `evaluation/` is `construction/weak_signal.json` (topic → `problem` / `solution` → validated signals) — curated from these candidates by a human annotation step, not generated by the pipeline. It covers 66 validated signals (34 problem-space and 32 solution-space) across 18 of the 25 target topics, giving 30 signal-bearing (topic, direction) pairs, and **ships with this repository**; the same signals (with grounding papers) are released on Hugging Face as `signals.jsonl`, from which the file can be regenerated:

```bash
python construction/scripts/build_weak_signal_json.py --download
```

### 2. Prediction — run the models

Generate weak-signal predictions with the API-only, RAG, and agentic systems. Topics come from `construction/topics.json`. See [`prediction/prediction_guide.md`](prediction/prediction_guide.md).

```bash
cd prediction
python qwen3_5_397b.py --output-dir ./outputs
```

> The DR-Tulu and Tongyi DeepResearch agents depend on their upstream repositories, which are cloned separately (see [Upstream agent repositories](#upstream-agent-repositories)) and passed via `--dr-tulu-dir` / `--tongyi-dir`.

> **RAG systems reuse the construction corpus.** `qwen3_8B_rag.py` and `qwen3_30B_rag.py` read the pre-fetched pools under `construction/papers/` (`--papers-dir`) when they exist, and only fall back to querying Semantic Scholar live when that directory is missing. Running step 1 first — or keeping an existing `construction/papers/` tree — is therefore the intended path; the live fallback issues a narrower query set for `qwen3_30B_rag.py` (topic only, without the `topics.json` paraphrases).

### 3. Evaluation — score predictions against ground truth

Evaluate predicted signals against `construction/weak_signal.json` across four default settings (set / signal level × BERTScore / LLM judge), plus an opt-in fifth setting — Coverage@K, a recall-only metric over the model's top-K ranked predictions. See [`evaluation/evaluation_guide.md`](evaluation/evaluation_guide.md).

```bash
python evaluation/run_all.py --settings 1 2 3 4     # the four default settings
python evaluation/run_all.py --settings 5           # Coverage@10 (opt-in)
```
